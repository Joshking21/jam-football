# Scouting and transfers reference (made 23 Nov at the user's request)

`scouting.png` is the target; `index.html` is its static source (it uses the shared `base.css` and `base.js`). Build §11.10 Transfers and §12.12 Knowledge to match it. Where this file and the SPEC differ, this file wins on layout and look; the SPEC wins on rules and numbers.

- **Left: a card-index drawer** (wooden box) of the shortlist. Each index card has a position · club tab, name, club · age, OVR (a band like 77-81 when knowledge is under 100%), and a knowledge bar. The selected card pulls out with a blue outline. Filters: Shortlist, Search, By position, Free agents.
- **Middle: the scout's report sheet** (letterhead "Scout's report", file number):
  - **Header:** printed photo, name and facts, position and trait chips (traits only once knowledge is 50% or more), the OVR band and knowledge %.
  - **Attributes:** shown as **ranges** with a hatched band for the unknown part (§12.12); exact values once scouted.
  - **Verdict box:** Would he start? (vs your current player at that slot), Asking price (estimate; a range until scouted or countered), Would he come? (§12.13.3 rules in words).
  - **Scout's note:** a quote from templates.
  - **Actions:** Make an offer (opens the bid and contract talk flow; disabled outside windows, with the reason), Scout him fully, Remove.
  - **"Him against your [position]":** comparison bars vs the user's current starter in that slot.
  - A red TARGET stamp once shortlisted.
- **Right rail:** window status (Closed / Day 1 / Day 2 / Deadline Day), budgets, your scouts this round (with a free-slot call to action), and Theo's line.

All names, numbers and colours in the image are **sample data**. Always use the game's real data.
